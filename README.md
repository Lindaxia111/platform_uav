# 多无人机系统建模与 AFSIM 验证工作台 · 原型 0.1

这是从讨论方案推进的第一个本地可运行原型，目标是验证“模块化工程模型 → 算法规划 → AFSIM 场景生成 → 实际回放 → 差异与需求证据”。

## 启动

在本目录双击 **启动平台.cmd**。需要本机可用的 Python 3.12（含 Tkinter），默认 AFSIM 安装目录为 `D:\afsim\afsim-2.9.0-win64`。当前实现仅使用 Python 标准库和安装附带的 `pymystic`，无需额外安装依赖。

1. 在“工程建模”中选择模块并修改参数；切换模块时自动应用格式有效的参数。
2. 在“检查与执行”中确认 AFSIM 路径、仿真时限和需求阈值。
3. 点击“检查工程模型”，修正错误；警告说明当前模型的简化范围。
4. 点击“生成场景并运行 A/B 比较”。
5. 在“比较结果”查看差异、需求判定、轨迹预览和证据目录。

每次运行结果保存在 `%TEMP%\uav_workbench_runs` 的独立目录。这里使用 ASCII 运行编号，以减少 AFSIM 对复杂路径的兼容问题。关闭软件不会删除已有结果。“另存工程”保存当前模型及参数，不修改历史实验快照。

已验证的示例结果位于 `examples/results/20261027_183740_6a6cec2a/preview.html`，可直接打开[演示预览](examples/results/20261027_183740_6a6cec2a/preview.html)；历史测试结果见 [原型验证记录](docs/原型验证记录.md)。

在 AFSIM 中看动态回放，使用 Mystic 打开运行目录中的 `replay.aer`；查看场景定义，使用 Wizard 打开 `scenario.txt`。具体路径和命令见 [AFSIM 启动与查看说明](docs/AFSIM_GUIDE.md)。

## 已实现

- 五种模块：区域覆盖任务、无人机编组、任务分配器、公共航线生成器和覆盖评价器。
- 类型化端口与必需输入检查，受限行为模板，参数范围和单位检查。
- 需求—能力—功能—责任模块—验证用例的追踪与结果关联。
- 两种离线分配基线：顺序轮询、预计完成时间贪心。
- 算法包独立子进程调用、规划超时、输出合法性检查、源码快照与内容哈希。
- 自动生成 AFSIM 平台类型、实例、航线和日志配置，以及模型到生成文件的来源映射。
- 实际调用本机 Mission，使用本地 `pymystic` 解析 AER 位置状态。
- 基于实际回放轨迹的覆盖率、达到覆盖阈值时间、总航程和成员间重叠覆盖。
- 逐项需求判定、A/B 原始差值与相对差值、静态实验结果预览。
- 失败记录、生成场景、算法请求及结果、引擎日志、回放和评价方法归档。

## 当前支持范围

第一版使用**固定模块组合和参数化建模**，没有自由拖拽增加模块、任意连线或任意流程图编译。结构图用于选择模块和展示连接。后续可在稳定的工程模型与生成器之上扩展图形建模。

仅支持小范围平坦矩形区域，固定高度、简化空中运动和全程启用的理想圆形覆盖足迹。公共航线生成器将任务条带按分配次序连接，条带方向由离当前端点距离确定。转场路径也计算覆盖。到达航线末端后采用简化停止策略，这不是实机固定翼飞行模型。

覆盖率以等面积网格中心代表面积，实际轨迹相邻采样点间按直线扫掠计算；达到覆盖阈值的时间采用轨迹段终点时间，有采样和弯道离散化误差。总航程同样来自采样轨迹，不是高保真能耗结果。

当前比较是**单个确定性任务实例**，不包含统计置信区间、显著性、等效性或非劣性结论。指标改善不等于需求满足。未达到覆盖阈值时，相应时间保留为空，不以仿真结束时间代替。

尚未实现通信、共享计算资源、真实探测概率、碰撞规避、真实续航、在线 Python 控制、变更影响传播和定向测试选择。它们属于后续方向。报告当前只是验证数据闭环的预览，正式类型和版式尚未确定。

## 接入自己的算法

复制 `algorithms/round_robin`，修改 `manifest.json` 中的标识、名称和版本，在 `algorithm.py` 中实现 `plan(request)`。清单约定为：

```json
{
  "id": "my_allocator",
  "name": "我的任务分配算法",
  "version": "0.1.0",
  "api_version": "0.1",
  "category": "task_allocation",
  "execution_mode": "offline_plan",
  "entrypoint": "algorithm.py:plan",
  "parameters": {}
}
```

request 包含 `members`（编号、速度和初始位置）、`tasks`（条带编号、x 坐标、南北端点与长度）、`seed`、`parameters` 和公共约束。坐标为以工程原点定义的局部东、北坐标，单位米。算法负责读取种子并初始化其自身随机源；平台不会替用户代码的所有随机库自动设置种子。

返回格式：

```python
{
    "status": "ok",
    "assignments": [
        {"task_id": "STRIP_001", "uav_id": "UAV_1"}
    ],
    "unassigned": []
}
```

示例只展示一条记录；实际必须说明全部任务的归属。同一无人机的执行次序取其记录在 `assignments` 列表中的顺序。不允许重复、未知成员和静默遗漏。部分可行时返回 `status: partial`，未分配任务逐项提供 `task_id` 与 `reason`；全部不可行返回 `infeasible`，不产生仿真指标。

在界面的任务分配模块中选择算法包目录即可。包中可放额外 Python 模块和模型文件；算法使用本机 Python 环境，暂不自动安装依赖或支持不同运行环境。独立进程用于生命周期、日志和超时管理，不是运行不可信代码的安全容器。规划预算包含进程启动、导入和执行，记录的是本机耗时，不代表机载实时性。

## 工程模型与证据

默认模型：`examples/coverage_project.json`。模型包含模块、参数、类型化连接、固定行为流程、能力、功能、需求和追踪关系。各次运行先解析为有效配置，再生成场景；不从任意修改过的 AFSIM 文本自动反推模型。

结果目录内：

- `engineering_model.json`：工程快照和有效参数。
- `common_task_instance.json`：A/B 共用任务输入。
- `comparison.json`：算法及运行环境、模型哈希、差异和失败状态。
- `run_00` / `run_01`：各算法的源码快照、输入输出、场景、来源映射、日志、回放、实际轨迹、网格及指标。
- `preview.html`：结果与轨迹预览，可在本机浏览器打开。

源包和引擎安装未被修改；各次实验保存实际调用路径。源码快照便于复查，完整复现还需要相同引擎、插件、Python 依赖和模型条件。

## 命令入口与检查

在项目根目录执行：

```powershell
python -m workbench check
python -m workbench compare
python -m workbench gui
python -X utf8 -B scripts/verify.py
```

`python main.py check/compare/gui` 继续可用。开发检查的 `--static-only` 选项仅检查目录、语法、JSON 和本地链接；`--with-afsim` 额外执行真实 AFSIM A/B 比较并保存在 `artifacts/runs/`。

运行平台时可用 `--model 工程文件路径` 指定模型，用 `--output-root 输出目录` 指定结果根目录，例如 `python -m workbench compare --output-root artifacts/runs`。算法包相对路径按本项目根目录解析，也可使用绝对路径。默认结果仍写入 `%TEMP%\uav_workbench_runs`，没有 `TEMP` 时回退到 `artifacts/runs/`。

开发检查日志位于 `artifacts/verification/`。测试产物位于 `artifacts/test_runs/`，成功用例自动清理，失败时保留。迁移前的测试产物和缓存归档在 `artifacts/archive/`。
