# 开发规范

本规范适用于 `D:\platform` 的后续开发。开发前先阅读根目录 `AGENTS.md` 和 `SESSION_HANDOFF.md`，再根据任务阅读本文及 [架构说明](ARCHITECTURE.md)。改变约定时，同步修改文档与检查脚本。

## 目录职责

| 位置 | 允许放置的内容 |
|---|---|
| 根目录 | README、协作与交接文件、编辑器配置、兼容启动入口、三个用户用的 CMD 脚本 |
| `workbench/` | 平台 Python 包；界面、模型、实验、引擎适配、评价和报告 |
| `algorithms/<algorithm_id>/` | 独立算法包，每包必须有 `manifest.json` 和声明的入口 |
| `examples/coverage_project.json` | 默认可运行工程模型；后续其他示例工程也放在 `examples/` |
| `examples/results/<comparison_id>/` | 经验证并随项目保留的演示证据快照 |
| `docs/` | 使用说明、架构、开发规范、验证记录和结构变更记录 |
| `scripts/` | 开发检查及维护脚本；通过项目根目录定位资源 |
| `tests/` | `unittest` 自动化测试，文件名使用 `test_*.py` |
| `artifacts/` | 本机日志、开发仿真结果、测试证据、验证日志和历史归档，均不纳入版本管理 |

根目录不得新增随手笔记、日志、截图、复制的旧源码、试验脚本或运行目录。新增根目录条目确有需要时，同步更新 `scripts/verify.py` 中的登记表并说明用途。`.git`、虚拟环境和常用编辑器配置目录由检查脚本单独允许。

## 模块边界

- `gui.py` 处理交互、参数写回与结果展示；仿真通过工作线程调用实验编排，不在界面中重复指标计算或拼接场景。
- `cli.py` 负责命令解析；`main.py` 和 `__main__.py` 只转发入口，三处不得各自维护业务逻辑。
- `model.py` 负责模型读取、合法性检查和归一化；修改结构、端口、参数或单位时，在该处集中校验。
- `planning.py` 与 `plugin_worker.py` 负责算法调用、快照、超时、输出检查和公共航线；具体分配策略写在 `algorithms/`。
- `afsim.py` 负责场景生成、引擎调用和回放解析；`metrics.py` 基于实际回放数据计算指标；`report.py` 负责展示已有结果。
- `experiment.py` 编排上述步骤并保存证据。底层模型、几何、算法与引擎模块不得反向依赖 GUI 或 CLI。

维持当前直接可运行的 Python 包布局。新增子包、依赖或构建流程应服务于实际功能，不为单纯重排目录引入框架。

## 命名、编码与路径

- Python 目标环境为 3.12。新增 Python 文件、模块、函数和变量采用 `snake_case`；类名使用 `PascalCase`；常量使用 `UPPER_SNAKE_CASE`。
- 新增代码使用 4 个空格缩进；JSON 使用 2 个空格；文本文件统一 UTF-8。Python、Markdown 和 JSON 使用 LF，Windows CMD 使用 CRLF，具体设置见根目录 `.editorconfig`。
- 新增代码的函数保持单一职责；对非直观的单位换算、几何公式和假设写明原因。优先标准库；需要第三方依赖时，提供依赖声明、安装说明和验证方法。
- 业务代码用 `pathlib.Path`。项目内资源基于 `PROJECT_ROOT` 定位，禁止写死桌面源目录、开发者用户名或依赖调用者当前目录。
- 工程里的算法相对路径始终相对于项目根目录解析；显式选择的绝对算法路径继续支持。`examples/results/latest.json` 中的路径相对于该索引文件。
- AFSIM 路径从工程的 `engine.afsim_home` 获取；外部程序通过参数列表和明确的工作目录调用。
- 正式默认结果继续放在 `%TEMP%\uav_workbench_runs`；没有 `TEMP` 时落到 `artifacts/runs`。开发运行可用 `--output-root artifacts/runs`。引擎运行目录和平台编号优先使用 ASCII，以保持已有兼容策略。
- `.aer` 按二进制保存；`examples/results/` 中的历史证据禁止 Git 自动转换换行符，包含算法源码快照，以保留原始字节和哈希。该只读证据目录免于 Git 空白格式检查，避免将原始 CRLF 或引擎日志重新格式化；开发源码仍按配置检查。算法快照和历史结果中的原始绝对调用路径属于证据，不按当前机器路径改写。

## 算法与数据契约

- 算法包必须声明标识、版本、`api_version`、分类、执行模式和入口。当前接口为 `api_version: 0.1`、`task_allocation`、`offline_plan` 和 `plan(request)`。
- `assignments` 与 `unassigned` 必须覆盖全部任务；任务不得重复或引用未知成员，未分配任务必须有原因。`ok`、`partial`、`infeasible` 应与内容一致。
- 坐标使用局部东、北米制，时间为秒。新增指标与参数应标明单位，拒绝 NaN、Infinity、用布尔值代替数值等非法数据。
- 算法进程保留日志、超时诊断、实际源码快照与哈希；失败状态写入实验结果。不能将失败运行静默排除，也不能将进程隔离描述为不可信代码安全沙箱。
- A/B 使用同一任务实例、约束、公共航线和评价方法。指标改善与需求达标分别表达；未达到阈值的时间为 `null`，不使用仿真结束时间替代。
- 当前工程版本与算法接口版本均为 0.1。改变兼容格式前应更新版本、解析与校验逻辑、示例、兼容说明和对应测试。

## 产物与历史证据

- 每次仿真生成独立目录，保存工程与算法快照、请求/结果、场景、来源映射、日志、回放、轨迹和指标。
- 已验证的 `examples/results/` 快照只读使用。新增实验写入新目录，验证后再选取为演示；只能修改用于导航的 `latest.json`，不得重写旧实验使其看起来匹配新实现。
- 历史 `.test_runs` 已归档到 `artifacts/archive/test_runs_20261027`；原 GUI 日志在 `artifacts/logs/`。归档内容不会被验证脚本当成当前源码或测试。
- 测试产物写入 `artifacts/test_runs/`；成功用例自动清理自身目录，失败用例保留诊断。验证日志写入 `artifacts/verification/`。清理历史产物时应先确认范围。

## 修改后的验证

统一入口：双击根目录 `检查项目.cmd`，或在根目录执行：

```powershell
python -X utf8 -B scripts/verify.py
```

该命令检查根目录登记、必需文件、Python 语法、示例 JSON、文档本地链接、演示预览链接，再运行全部单元/隐藏界面测试、默认模型检查和旧入口兼容性检查。默认模型检查要求本机 AFSIM 安装可访问；检查脚本不自动安装环境。

仅调整文档时可执行 `python -X utf8 -B scripts/verify.py --static-only`。修改源码、路径、启动方式或算法时执行完整检查；修改仿真生成、引擎适配、轨迹解析或指标口径时，还应执行真实引擎验证：

```powershell
python -X utf8 -B scripts/verify.py --with-afsim
```

真实运行的开发证据保存在 `artifacts/runs/`。测试通过不等于需求通过；默认示例即使完成运行，也可能没有达到覆盖率需求。交付时应报告实际运行的检查和未验证项，不能把历史检查写成此次结果。

新增或改变行为时补充相应成功、异常或边界测试；纯文档与简单可逆布局调整不要求为目录名本身编写重复测试。检查脚本覆盖自动检查项，模块职责和指标含义仍需在开发和评审时核对。

## 版本管理

- 仓库默认分支和当前开发主分支统一为 `main`，对应远程 `origin/main`；后续开发以此分支为基准。首次上传使用的 `master` 保留作历史分支。
- 提交前确认变更范围和相应验证结果，排除本机开发产物。同步远程使用正常推送，保留已有提交历史。

## 文档与会话交接

- 用户入口或路径变化，同步更新 `README.md`、相关使用说明和 `SESSION_HANDOFF.md`。
- 模块关系变化，同步更新 `docs/ARCHITECTURE.md`；目录和约束变化，同步更新本文、`AGENTS.md`、`scripts/verify.py` 与 `docs/STRUCTURE_CHANGELOG.md`。
- 完成阶段性工作或准备切换长会话时，更新交接摘要，写明本次变更、测试、未完成项和下一步。保留用户已确认的约定。
